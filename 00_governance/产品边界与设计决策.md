# GitGit + MinIOS3 产品边界及变更决策（ADR-GG-001）

> 2026-10-26 | 决策级别：架构设计草案，待签署

## 权威与部署

| 域 | 权威拥有者 | 支持库/服务 | 不得混淆 |
|---|---|---|---|
| Commit/Ref/Branch/Tag/Merge | **GitGit Rust Core (自研)** | 可选Git互操作Adapter | GitLFS指针和外部GitServer不是原生权威 |
| AssetRevision/Review/Lock/Dependency | GitGit Core | 可选媒体Plugin | 不以S3版本覆盖媒体版本 |
| ContentManifest/Chunk/Storage receipt | **MinIOS3 Rust Core (自研)** | redb/OpenRaft、EC/CDC | 内容按Receipt完成Durable后才可提交 |
| S3 API/迁移/ObjectLock/后端物理Version | MinIOS3 Gateway/Catalog | OpenDAL/AWS Rust SDK | Provider版本可能在迁移后改变 |
| 转码/预览/语义差异 | 单独沙盒Worker | 按许可选择开源解析器 | 派生数据不覆盖原件 |

## 许可证策略

核心程序优先 MIT/Apache-2.0/BSD；许可审查以**实际锁定版本及传递依赖SBOM**为准。OpenRaft、redb、Apache OpenDAL、Tokio、Axum、Tonic、Cedar、RustCrypto以及前端Vue/ECharts为候选而非不可撤销绑定；FFmpeg作为可选独立Worker严格限制构建许可。不存在“所有开源组件无需审查”的承诺。

## 高风险设计冻结前条件

1. GitGit事务状态机、Ref CAS持久化、跨服务Receipt协议与真实PoC验证。
2. 20GiB流式CDC写路径、重传与SHA校验内存曲线。
3. 文件格式Adapter的安全性、确定性、超时与许可证签署。
4. 完整GitGit可达性GC与跨后端切换情况下的恢复证明。
5. Raft单Bucket单分片与跨分片LIST语义限制不因产品重新定位而消失。
