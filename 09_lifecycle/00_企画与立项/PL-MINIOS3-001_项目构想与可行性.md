# PL-MINIOS3-001 — 企画・構想及可行性说明书

> 状态：Draft / 设计基线v2.1 / 日期：2026-10-26 / 归属：GitGit + MinIOS3

## 1. 项目背景和机会
传统Git对大型二进制和媒体语义差异支持有限；仅使用S3对象版本难以支持Repo/Branch/Commit的版本语义、可审核的三方合并与依赖影响。目标是让GitGit成为**自研多媒体版本权威引擎**，MinIOS3负责**可靠内容存储、S3兼容和存储互换**。不以MinIO源码复刻、不以Git LFS作为主版本链路。

## 2. 产品价值与主要利益相关者
| 角色 | 待解决问题 | 可验收的价值 |
|---|---|---|
| 视频剪辑师/音频师 | 大型媒体同步和版本比较代价高 | 按需获取媒体、定位版本变化，保留可追溯来源 |
| 游戏/3D制作组 | 多资产依赖和二进制冲突 | AssetId稳定、依赖图、显式冲突及协作锁 |
| 架构/开发组 | Git项目版本与二进制资源脱节 | 同一Commit绑定不可变媒体内容清单 |
| 存储运维 | S3厂商锁定与迁移风险 | 统一端点、迁移验证、可恢复切换 |
| 安全/法务 | 来源、合规与历史误删 | 租户隔离、完整审计、WORM/法务保留优先 |

## 3. 投入与边界
E0优先交付GitGit原生Ref/Commit/Tree/AssetRevision、MinIOS3 CAS/Manifest、增量上传、可还原Checkout、基础S3接口。E1交付企业级HA/纠删码/多租户授权与协作，E2交付深入媒体语义分析。部署费用、S3第三方费用、审计和运维费用不属于“开源软件零许可证费”范畴。

## 4. 自研/采购决策
核心逻辑为Rust自主实现；依赖仅选许可证可审查的开源库，推荐MIT/Apache/BSD；外围Keycloak、OpenBao等独立服务可以选用不同许可证但必须审查。所有crate/worker版本与SPDX须在正式发行前以Lockfile+SBOM冻结。

## 5. 成立条件 / 否决条件
成立：完成20GiB媒体上传→Commit→Checkout→SHA256还原的端到端PoC；断外网仍可运行；禁用LFS仍可使用。否决：已ACK Commit可引用缺块、GC可误删受保护历史、无法证明迁移不丢ACK写入、许可证无法合规交付。上述条件不得以纸面设计覆盖作为通过。

## 6. 项目成功判据
按E0/E1/E2独立签署门禁；业务目标以版本恢复正确性与用户可完成任务为先，性能目标需经基准测试与产品干系人协商，未冻结的SLO不写成承诺。参照UC-GG-01～UC-GG-10及FR-GG/FR-MV系列。
